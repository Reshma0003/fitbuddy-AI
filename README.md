# FitBuddy – AI Fitness Plan Generator using Gemini

FitBuddy is a FastAPI + Jinja2 + SQLite web application based on the supplied project documentation. It accepts a user's name, user ID, age, weight, fitness goal, and workout intensity, then uses Google's Gemini API to generate a 7-day workout plan and a nutrition/recovery tip. Users can submit feedback and have Gemini regenerate the complete plan. An admin page shows stored users and original/updated plans.

## What was updated from the supplied documentation

The supplied document describes Gemini 1.5 Pro/Flash and the older `google-generativeai` SDK. This implementation uses Google's current `google-genai` Python SDK and configurable model names. The default model is `gemini-3.8-flash`; change `GEMINI_WORKOUT_MODEL` if your Google AI account has access to another current model.

## Features

- FastAPI backend
- Jinja2 frontend
- SQLite + SQLAlchemy persistence
- Gemini-powered 7-day plan generation
- Gemini-powered nutrition/recovery tip
- Gemini feedback-based plan revision
- HTML pages and JSON API endpoints
- FastAPI Swagger documentation at `/docs`
- Token-protected admin dashboard
- Input validation and friendly error pages
- Automated tests with Gemini mocked, so tests do not spend API quota

## VS Code setup – Windows

### 1. Install prerequisites

Install Python 3.11+ and VS Code. Open the FitBuddy folder in VS Code.

### 2. Create a virtual environment

Open **Terminal → New Terminal**:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, use Command Prompt:

```cmd
.venv\Scripts\activate
```

### 3. Install dependencies

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Add your Gemini API key

Copy `.env.example` to `.env` and set:

```env
GEMINI_API_KEY=YOUR_REAL_GEMINI_API_KEY
ADMIN_TOKEN=my-secret-admin-token
```

Keep `.env` private and never commit it to Git.

### 5. Start the application

```powershell
uvicorn app.main:app --reload
```

Open:

- Website: http://127.0.0.1:8000
- Swagger API docs: http://127.0.0.1:8000/docs
- Health check: http://127.0.0.1:8000/api/health
- Admin: http://127.0.0.1:8000/view-all-users

## How to test the complete application manually

1. Open the home page.
2. Enter a test profile, for example:
   - Name: Abinaya
   - User ID: demo001
   - Age: 21
   - Weight: 60
   - Goal: Muscle gain
   - Intensity: Medium
3. Click **Generate with Gemini**.
4. Confirm that a 7-day plan and nutrition/recovery tip appear.
5. Submit feedback such as `Add more cardio and make Day 7 a recovery day.`
6. Confirm the revised complete 7-day plan appears.
7. Open `/view-all-users` and enter the `ADMIN_TOKEN` from `.env`.
8. Confirm the user, original plan, feedback, and updated plan are stored.

Swagger is available at `/docs`.

```json
{
  "name": "Abinaya",
  "user_id": "demo001",
  "age": 21,
  "weight": 60,
  "goal": "muscle gain",
  "intensity": "medium"
}
```

### Update plan

`POST /api/submit-feedback`

```json
{
  "user_id": "demo001",
  "feedback": "Add more cardio and make Day 7 a recovery day."
}
```

## Automated tests

With the virtual environment activated:

```bash
pytest -q
```

The tests mock the Gemini service, so they verify routing, database persistence, feedback updating, and health behavior without requiring an API key or consuming Gemini quota.

## Gemini configuration

The integration is centralized in `app/gemini_service.py`. The application calls the current Google GenAI Python SDK with `client.models.generate_content(...)`. Workout generation and nutrition generation are separate functions, matching the modular AI layer described in the project document.

If a model is unavailable to your API key, change the model names in `.env`. The code does not hard-code an API key.
